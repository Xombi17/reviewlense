## Problem Statement

E-commerce platforms like Amazon India host thousands of product reviews per listing. A user researching a boAt speaker or a Mamaearth skincare product cannot realistically read 3000+ reviews before making a purchase decision. Existing star-rating systems collapse all nuance into a single number and give no signal about *why* customers are happy or unhappy.

Beyond the consumer problem, most academic sentiment analysis projects stop at accuracy metrics and ignore a critical real-world concern — the model's own uncertainty. A classifier that is 51% confident in a prediction is essentially guessing, and presenting that prediction with the same weight as a 97% confident one is misleading.

**ReviewLens AI solves both:** it gives users meaningful insight into product reviews and is honest about when it doesn't know.

---

## Goals

### Primary (Assignment Requirements)
- Classify sentiment of product reviews as Positive or Negative
- Report where the model is unreliable with concrete examples and analysis

### Secondary (Product Quality)
- Extract aspect-level sentiment from reviews (battery, sound, delivery, etc.)
- Provide a confidence score and reliability flag per prediction
- Support batch analysis via CSV upload
- Generate aggregate insights across a full review dataset

### Tertiary (Portfolio Value)
- Present as a real product with a clean Next.js frontend
- Expose a documented FastAPI backend that could be deployed
- Produce comparison metrics across multiple ML models

---

## Non-Goals

- Real-time scraping of Amazon/boAt reviews (use pre-collected Kaggle datasets)
- User authentication or saved history
- Mobile app
- Multilingual support (English reviews only)
- Production deployment (localhost demo is sufficient)
- BERT or transformer models (classical ML only)

## Architecture Overview

```
User Browser (Next.js :3000)
    ↓ HTTP/JSON
FastAPI Backend (:8000)
    ↓ joblib
ML Models (.pkl files)
    ↑ (offline)
Jupyter Notebooks → Kaggle CSV
```

**Three API endpoints:**
- `POST /predict` — single review analysis
- `POST /batch` — CSV upload + aggregate analysis
- `GET /stats` — precomputed model + dataset statistics

---

## Key Design Decisions

1. **Classical ML only** — NB, LR, LinearSVM. No transformers. BERT mentioned as future work.
2. **Reliability-first** — Every prediction carries a confidence score, reliability tier (HIGH/MEDIUM/LOW), and failure flags.
3. **Keyword-based aspect extraction** — Not deep learning. Fast, explainable, sufficient for mini-project scope.
4. **Trust score heuristics** — Lightweight fake-review detector. Score 0–1 with `suspicious_review` flag.
5. **No database** — All state is in-memory (model objects) or files (CSV, pkl, json).
6. **Models loaded once at startup** — FastAPI lifespan context, not on every request.

## Dataset

- **Source:** Kaggle Amazon Product Reviews (Electronics / audio category)
- **Minimum size:** 10,000 reviews after cleaning
- **Label mapping:** Stars 4–5 → Positive (1) | Stars 1–2 → Negative (0) | Star 3 → Discarded
- **Columns used:** `reviewText` (features), `overall` (label derivation)
